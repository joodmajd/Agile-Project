# Week 12 capstone demo — 10 minutes + 5 minute Q&A

Practice to the brief's timings; use the real deployed/Docker build and actual Jira/CI evidence. Every member speaks. Avoid slides for product features; demonstrate the running MVP.

| Time | Speaker | Demonstration |
|---|---|---|
| 0:00–1:00 | PO | Problem, three users, product vision, and key rule. |
| 1:00–2:00 | TA/author role | Create a tagged MCQ and show it remains a draft. |
| 2:00–3:00 | Instructor/reviewer role | Inspect and publish it; show the workflow state. |
| 3:00–5:00 | Student role | Choose a topic, take a random quiz, submit, show score, explanation, and history. Include the insufficient-question message if time permits. |
| 5:00–6:00 | Student/PO | Show all four MVP epics and key rule with a known test case. |
| 6:00–8:00 | Developer(s) | Show green CI on main, key-rule unit test, and one passing Gherkin scenario; point out pull request review. |
| 8:00–10:00 | SM | Show Jira backlog/Sprints, actual burndown or velocity, user feedback and resulting change, and top retrospective action. |
| 10:00–15:00 | Any member | Q&A; all members should be prepared to explain their own work and a design/test decision. |

## Demo readiness checklist

- [ ] Rehearsed to 10 minutes; every member has a speaking segment.
- [ ] Demo data reset and entirely invented; network and app startup checked.
- [ ] Ten published questions exist for the demonstrated course/week.
- [ ] One draft is available for review/publish flow.
- [ ] CI link, passing tests, Gherkin run, PR review, Jira chart, and feedback change open in tabs.
- [ ] Docker or deployment URL works on the demo machine; backup local run instructions ready.
- [ ] Peer evaluation form is handed in individually, including self-rating.
