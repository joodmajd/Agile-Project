# Sprint plan and ceremony evidence

Sprint 0 is the Week 7 setup sprint; Sprints 1–4 are one-week delivery sprints in Weeks 8–11. Dates follow the faculty calendar. The team should create one Jira project and record the actual sprint start/end dates there.

## Required working agreements

- Sprint Planning at the start of the lab: record goal, capacity, selected issue keys, estimates, and any dependencies.
- Stand-up at least three times per week: SM records date, attendees, progress, next step, and blockers (briefly).
- Sprint Review at week end: show the running increment to TA; PO accepts/rejects each completed story with reason.
- Retrospective: Start / Stop / Continue, with one named action owner and due sprint.
- Rotate the PO and SM at the start of Sprint 3 (Week 10). Pick two different people for the new roles; both outgoing roles must also be distinct.
- Add instructor and TA to the shared GitHub repository and Jira project. Record the fact in the registration hand-in, but do not publish private credentials.

## Sprint 0 checklist (Week 7)

- [ ] Submit the registration form and rank three project ideas; obtain TA approval for Practice Quiz Bank.
- [ ] Agree one-paragraph vision and MVP boundary.
- [ ] Create shared GitHub repository and Jira project; add instructor and TA.
- [ ] Enter at least 15 prioritized, estimated INVEST stories with acceptance criteria.
- [ ] Agree and commit the team Definition of Done.
- [ ] Record team roster, GitHub usernames, role assignments, URLs, TA signature/date.

## Sprint records

Use the files `sprint-1-review.md` through `sprint-4-review.md` and `retro-1.md` through `retro-4.md` as per-sprint records. Create `retro-0.md` for the setup sprint as well. Keep stand-up notes and burndown/velocity in Jira or link/export them in the review. Templates are intentionally blank so the team can enter factual outcomes.

## Burndown / velocity evidence

At every planning, snapshot remaining work by day in Jira. At review, record planned points, accepted points, and a Jira chart/export link. Velocity is **accepted story points** per sprint, not effort logged. The Week 12 demo should show the actual Jira chart or a labeled export; do not present the sample allocation in `backlog.md` as achieved velocity.
